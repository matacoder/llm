# Локальная LLM система (PoC)

Полностью локальное решение на базе Ollama и Open WebUI с интерфейсом как ChatGPT и автоматической синхронизацией документов.

## 🚀 Возможности

- ✅ Веб-интерфейс как ChatGPT
- ✅ **Автоматическая** работа с документами (RAG)
- ✅ Поддержка русского и английского языков
- ✅ Мультиюзерная система с историей чатов
- ✅ Работает полностью локально (без интернета)
- ✅ Использует NVIDIA GPU
- ✅ Доступен только в локальной сети

## ⚡ Quick Start (5 минут)

### 1. Запустите систему
```bash
docker compose up -d
```

### 2. Загрузите модели
```bash
# Основная модель для чата
docker exec -it ollama ollama pull qwen2.5:7b

# Модель для работы с документами (выберите одну)
docker exec -it ollama ollama pull mxbai-embed-large  # Рекомендуется для русского
# ИЛИ
docker exec -it ollama ollama pull nomic-embed-text   # Универсальная модель
```

### 3. Откройте веб-интерфейс и настройте RAG
Откройте браузер: **http://localhost:3000**
- Создайте аккаунт администратора
- Войдите в систему
- Перейдите в **Settings → Admin Settings → Documents**

**Настройте параметры RAG для точного поиска:**
- **Embedding Model:** выберите `mxbai-embed-large`
- **Chunk Size:** установите `200` или `250` (не оставляйте 400!)
- **Chunk Overlap:** установите `40` или `50`
- **Hybrid Search:** включите ✓
- **Top K:** установите `15`
- Нажмите **Save**

> Подробнее: см. раздел "Настройка RAG" ниже

### 4. Настройте автосинхронизацию документов
```bash
# 1. Создайте API ключ в Open WebUI
#    Settings → Account → API Keys → Create new secret key

# 2. Создайте коллекцию Knowledge
#    Workspace → Knowledge → Create new knowledge

# 3. Добавьте в .env (скопируйте из .env.example)
nano .env
# OWUI_TOKEN=ваш-api-токен
# OWUI_KNOWLEDGE_ID=id-коллекции

# 4. Перезапустите сервис синхронизации
docker compose restart rag-sync
```

### 5. Добавьте документы
```bash
# Просто копируйте файлы в папку documents/
cp ваши-документы.pdf documents/

# Через 1-3 секунды они автоматически загрузятся в систему!
```

**Готово!** 🎉 Теперь можете задавать вопросы по документам в чате.

## 📚 Работа с документами

### ⚙️ Настройка RAG (Retrieval Augmented Generation)

RAG позволяет LLM находить информацию в ваших документах и отвечать на вопросы с использованием этого контекста.

> **⚠️ ВАЖНО:** Настройки RAG в `docker-compose.yml` (CHUNK_SIZE, TOP_K и др.) работают **только при первом запуске**. Для изменения настроек всегда используйте **веб-интерфейс Open WebUI**.

#### Рекомендуемые настройки для точного поиска

Откройте: **Settings → Admin Settings → Documents**

**1. Модель эмбеддингов:**
- `mxbai-embed-large` - лучшая для русского языка (669MB) ⭐ РЕКОМЕНДУЕТСЯ
- `nomic-embed-text` - универсальная модель (274MB)

**Как загрузить и настроить:**
```bash
# Загрузите модель
docker exec -it ollama ollama pull mxbai-embed-large
```

В веб-интерфейсе:
- **Settings → Admin Settings → Documents**
- **Embedding Model:** выберите `mxbai-embed-large`
- **Save**

**2. Параметры разбивки текста:**

| Параметр | Рекомендуется | Почему |
|----------|---------------|---------|
| **Text Splitter** | RecursiveCharacter | Учитывает структуру текста |
| **Chunk Size** | 200-250 | Меньше чанки = точнее поиск (400 слишком большой!) |
| **Chunk Overlap** | 40-50 | Сохраняет контекст между чанками |

> **Проблема больших чанков:** При Chunk Size = 400 система может захватывать целые списки литературы вместо основного содержимого. Уменьшение до 200-250 символов решает эту проблему.

**3. Параметры поиска:**

| Параметр | Рекомендуется | Описание |
|----------|---------------|----------|
| **Hybrid Search** | ✓ Включить | Комбинация векторного + полнотекстового поиска |
| **Top K** | 15 | Количество лучших чанков для LLM (больше = лучше выбор) |
| **Full Context Mode** | ✗ Выключить | Изменяет весь интерфейс, отключает некоторые настройки |

**4. RAG Template (опционально):**

Для игнорирования списков литературы добавьте такой промпт в **RAG Template**:

```
Using the context provided, answer the question accurately.
IGNORE: bibliography sections, reference lists, citations, page numbers.
FOCUS ON: main content, instructions, procedures, descriptions.

Context:
{context}

Question: {query}
```

**5. Переиндексация после изменения настроек:**

⚠️ После изменения Chunk Size, Overlap или модели эмбеддингов **обязательно переиндексируйте документы!**

**Способ 1: Через автосинхронизацию**
```bash
# Временно переместите документы
mv documents/*.pdf /tmp/

# Дождитесь удаления (проверьте логи)
docker compose logs -f rag-sync

# Верните документы
mv /tmp/*.pdf documents/
```

**Способ 2: Через веб-интерфейс**
- Удалите документы из коллекции Knowledge
- Загрузите их заново

**Способ 3: Кнопка Reindex (если доступна)**
- В настройках может быть кнопка **"Reindex"** для автоматической переиндексации

### 🔄 Автоматическая синхронизация (рекомендуется)

Система включает **умный сервис автоматической синхронизации** документов с мгновенной обработкой!

#### Первая настройка (5 минут)

**1. Создайте API токен:**
- Откройте Open WebUI: http://localhost:3000
- Перейдите: **Settings → Account → API Keys**
- Нажмите **Create new secret key**
- Скопируйте токен (начинается с `sk-`)

**2. Создайте коллекцию Knowledge:**
- Перейдите: **Workspace → Knowledge**
- Нажмите **+ Create new knowledge**
- Введите название (например, "Документы компании")
- Скопируйте **ID коллекции** из URL адресной строки
  - URL: `http://localhost:3000/workspace/knowledge/abc-123-def`
  - ID: `abc-123-def`

**3. Настройте переменные окружения:**
```bash
# Создайте .env из примера (если еще не создали)
cp .env.example .env

# Отредактируйте .env
nano .env
```

Добавьте в `.env`:
```bash
# API токен из шага 1
OWUI_TOKEN=sk-ваш-токен-здесь

# ID коллекции из шага 2
OWUI_KNOWLEDGE_ID=abc-123-def
```

**4. Перезапустите сервис:**
```bash
docker compose restart rag-sync
```

#### Использование

**Теперь всё работает автоматически!**

```bash
# Просто копируйте файлы в папку documents/
cp ваши-документы.pdf documents/
cp презентация.pptx documents/
cp отчет.docx documents/

# Через 1-3 секунды они автоматически:
# ✅ Загрузятся в Open WebUI
# ✅ Добавятся в коллекцию Knowledge
# ✅ Проиндексируются для RAG
# ✅ Станут доступны для поиска в чатах
```

**Удаление файлов:**

```bash
# Удалите файл из папки documents/
rm documents/старый-документ.pdf

# Через максимум 5 минут (или при следующей проверке):
# ✅ Файл автоматически удалится из коллекции Knowledge
# ✅ Освободится место в векторной базе данных
# ✅ Файл больше не будет учитываться в RAG
```

**Примечание:** Система отслеживает файлы по внутреннему file_id из SQLite БД, поэтому:
- Переименование файла = новый файл (старый останется в коллекции до очистки)
- Изменение содержимого = перезагрузка файла (если размер/время изменения изменились)
- Удаление = автоматическое удаление из коллекции при следующей проверке

**Особенности:**
- ⚡ **Мгновенная обработка** - файлы обрабатываются в течение 1-3 секунд
- 🔍 **Умное отслеживание** - система использует SHA-256 хеши для избежания дублирования
- 🔄 **Автоматическое обновление** - измененные файлы перезагружаются автоматически
- 🗑️ **Автоматическая очистка** - удаленные файлы автоматически убираются из коллекции
- 🔄 **Автоматическая инвентаризация** - периодическая проверка и восстановление отсутствующих файлов
- 🛡️ **Защита от ошибок** - автоматические повторные попытки при сбоях сети
- 🔒 **Защита от race conditions** - блокировки для предотвращения конфликтов при параллельной работе
- 📊 **SQLite БД** - локальное хранение состояния синхронизации
- ⏱️ **Периодическая проверка** - очистка и инвентаризация каждые 5 минут

**Поддерживаемые форматы:**
- PDF (`.pdf`)
- Microsoft Word (`.doc`, `.docx`)
- Markdown (`.md`)
- Текстовые файлы (`.txt`)
- OpenDocument (`.odt`)
- Rich Text Format (`.rtf`)

#### Устранение проблем

**Файлы не синхронизируются:**
```bash
# 1. Проверьте логи
docker compose logs rag-sync | tail -50

# 2. Проверьте переменные окружения
docker compose exec rag-sync env | grep OWUI

# 3. Убедитесь, что токен и ID коллекции правильные
```

**Ошибка "401 Unauthorized":**
- Проверьте правильность API токена в `.env`
- Создайте новый токен в Open WebUI

**Ошибка "404 Not Found":**
- Проверьте правильность `OWUI_KNOWLEDGE_ID`
- Убедитесь, что коллекция существует

**Перезапуск с чистого состояния:**
```bash
# Остановите сервис
docker compose stop rag-sync

# Удалите базу данных состояния
rm -rf ./data/sync-state/

# Запустите снова
docker compose up -d rag-sync
```

#### Производительность

- **Скорость обработки:** 1-3 секунды на файл
- **Параллелизм:** 2 файла одновременно (настраивается)
- **Интервал очистки:** 300 секунд (5 минут, настраивается)
- **Память:** ~50MB RAM
- **CPU:** минимальное использование

Для массовой загрузки документов можно увеличить параллелизм в `docker-compose.yml`:
```yaml
environment:
  - CONCURRENCY=4        # Обрабатывать до 4 файлов одновременно
  - CLEANUP_INTERVAL=60  # Проверять удаленные файлы каждую минуту
```

**Примечания:**
- Увеличение `CONCURRENCY` ускоряет загрузку, но увеличивает нагрузку
- Уменьшение `CLEANUP_INTERVAL` ускоряет удаление файлов из коллекции
- Минимальный рекомендуемый `CLEANUP_INTERVAL`: 60 секунд

## 🐛 Решение проблем

### Контейнер не запускается

```bash
# Проверить логи
docker compose logs

# Пересоздать контейнеры
docker compose down
docker compose up -d
```

### GPU не используется

```bash
# Проверить NVIDIA Container Toolkit
docker run --rm --gpus all nvidia/cuda:12.0-base nvidia-smi

# Если не работает, переконфигурировать
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker
```

### Open WebUI не видит Ollama

```bash
# Проверить, что Ollama работает
docker exec -it ollama ollama list

# Проверить сетевое подключение
docker compose exec open-webui curl http://ollama:11434
```

### Медленная работа

1. Используйте меньшую модель (qwen2.5:7b вместо 14b)
2. Проверьте загрузку GPU: `nvidia-smi`
3. Убедитесь, что другие процессы не используют GPU

### Проблемы с автосинхронизацией документов

```bash
# Проверить логи синхронизации
```

### RAG находит неправильные фрагменты (списки литературы вместо основного текста)

**Проблема:** RAG возвращает библиографические списки, цитаты или нерелевантные части документа.

**Решение:**

1. **Уменьшите Chunk Size:**
   - **Settings → Admin Settings → Documents**
   - Установите **Chunk Size: 200-250** (вместо 400)
   - **Chunk Overlap: 40-50**

2. **Увеличьте Top K:**
   - Установите **Top K: 15** (даёт LLM больше вариантов на выбор)

3. **Включите Hybrid Search:**
   - Убедитесь что **Hybrid Search** включен ✓

4. **Добавьте RAG Template:**
   - Вставьте промпт для игнорирования библиографии (см. раздел "Настройка RAG" выше)

5. **Переиндексируйте документы:**
   ```bash
   # Удалите и добавьте документы заново
   mv documents/*.pdf /tmp/
   # Подождите 5 секунд
   mv /tmp/*.pdf documents/
   ```

> **Почему это помогает:** Большие чанки (400 символов) часто захватывают целые списки литературы, которые содержат много ключевых слов. Меньшие чанки (200-250) разбивают текст точнее и уменьшают вероятность захвата только библиографии.

Подробные инструкции смотрите в разделе "Настройка RAG" выше.
